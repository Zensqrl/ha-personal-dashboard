# Huzband Dashboard

## Project knowledge

- README.md — current implementation, setup, deployment, and current limitations.
- docs/vision.md — long-term product goals and design principles.
- docs/decision-logic-handoff.md — current decision rules and model behavior.
- docs/decision-flow.md — visual representation of the current data and decision pipeline.
- docs/roadmap/ — approved/proposed implementation roadmap artifacts.

Read only the documents relevant to the requested work.

## Planning workflow

For work that materially changes product architecture or adds a major
capability:

1. Compare the current implementation with docs/vision.md.
2. Update or propose roadmap artifacts first.
3. Do not create Todoist backlog entries until the user explicitly approves
   the roadmap.
4. After approval, use the Todoist Project Backlog skill to translate the
   approved near-term work into actionable backlog items.

Deferred roadmap capabilities remain documentation, not Todoist tasks.

## Implementation

For implementation tasks, use the approved roadmap and applicable technical
documentation rather than re-deriving product direction from scratch.
