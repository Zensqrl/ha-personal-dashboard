# Huzband Dashboard v0.1.1 implementation plan

Status: implemented and deployed September 21, 2026.

## Scope and decisions

Implement all eleven items in `v0.1-tweaks.md`, preserving the existing dashboard layout and source integrations.

1. **Measurement and recovery wording (1, 9):** Remove retrieval timestamps from Garmin detail rows. Live Body Battery, RHR and HRV attributes expose source days and fetch/sync metadata, but no verified per-value measurement time. Use the source day and explicit retained/fallback/unverified states. Keep chart endpoint times, remove `samples end`, combine HRV bounds into a readable comparison, and remove the generic recovery footer. Do not invent an RHR baseline.
2. **Weather and timeline (2–6):** Use compact local `h:mmam/pm` times; protect time tokens against wrapping. Quantify precipitation chance. Add `show_time_zone: false` as a presentation option. Document the existing `start_hour`/`end_hour` scheduling options and keep those consistent across cards. Use the exact requested subtitle and a collapsed `How this timeline works` disclosure with plain wording.
3. **Task and refresh diagnostics (7, 8):** Preserve safe read-error categories and last successful read times. Distinguish loading, connection failure, timeout, unsupported response, stale data and incomplete metadata. Show the appropriate recovery action. Give refresh a visible label, immediate progress, completion/partial-failure feedback, and cooldown feedback without bypassing retry limits.
4. **Dismiss/Undo (10):** Include session-only dismissal in v0.1.1. Share dismissed task IDs across the dashboard cards for the active HA connection/user; filter before both task ranking and timeline allocation. Fill from the remaining ranked tasks; provide Undo and an accurate empty state. Clear at the next local day or reload. Cross-device and persistent dismissal are v0.2+.
5. **Nutrition age (11):** Show checked-age bands separately from incomplete totals/targets and diary date. Use `>15 min`, `>30 min`, `>1 hr`, `>2 hr`; unknown or future timestamps remain unknown. Preserve the existing decision freshness policy. Retrieval age is not meal-edit time.

## Validation and release

- Test age boundaries, retained/fallback values, diagnostic categories, refresh outcomes, dismissal replacement/undo/reset, and timeline consistency.
- Build the self-contained module and exercise mobile and desktop synthetic previews, including dialogs, expanded notes, refresh and dismissal. Inspect screenshots for clipping and overflow.
- Re-read the installed resource and dashboard config before deployment. Save the current module locally for rollback. Update only this dashboard's existing resource through the supported Home Assistant API; preserve dashboard config and unrelated resources.
- Verify the installed module exactly matches the built artifact and the dashboard config hash is unchanged. Check authenticated rendering if a connected browser is available; otherwise explicitly record that limitation.
- Update README and `projectStatus.md`, commit source/tests/docs/bundle, push to the existing remote branch, and verify CI.

## Rollback

Restore the previously captured module content to the same dashboard resource ID through the resource API, then reload the frontend. No Home Assistant restart, integration update, or Recorder change is required.
